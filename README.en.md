# ComfyUI_Alpha_Anything

Native ComfyUI implementation of AlphaAnything: does not rely on diffusers, LoRA loads via ComfyUI's native loader, all model loading, text encoding, sampling, and VAE encoding use built-in nodes; VAE decoding reuses the native decoder, with only an alpha branch attached to its features. The extension only adds two runtime nodes (LoRA loading, RGBA decoding) and an optional Element Prompts prompt node. Connect upstream to a Generate Text (that supports image input text encoder) output layer plan that can read images, and you can extract a set of RGBA layers layer by layer in one queue: each layer gets a full sampling once, the foreground layer has true transparency, and the background layer is an opaque full image.

## What problem does it solve

AlphaAnything trained two things on RGB diffusion models (FLUX.2 Klein / Qwen-Image): transformer LoRA, and an alpha decoding branch.

- RGB generation proceeds normally, alpha **does not enter latent**.
- During decoding, the alpha branch bypasses to read intermediate features (conv_in / mid / various up stage) from the RGB VAE decoder, predicts alpha, and maps it to 0–1.
- Therefore, the official implementation must modify the diffusers decoding process, making it impossible to directly apply the native ComfyUI workflow.

This extension hands over all the parts that ComfyUI already has to native nodes, only adding two things:

- **LoRA loading**: Load official LoRA weights into the MODEL after converting them according to the alpha/rank in the adapter configuration, and pass the alpha branch weights down with the adapter.
- **Decoding**: During the native `vae.decode` execution process, hook the decoder feature to drive the alpha branch, outputting 4-channel RGBA.

✨ **RGB pixel consistency**: The RGB channels are identical to the result of directly calling the native `vae.decode` (difference is 0), with alpha generated by the bypass branch.

✨ **Intensity automatic conversion**: `strength = 1.0` is the official intensity; the `alpha / rank` in the adapter configuration will be automatically multiplied in.

✨ **Adapter automatic download**: Only read `ComfyUI/models/alphaanything/`, create the directory automatically if it doesn't exist; download the weight file automatically on the first execution if missing, prioritizing the Hugging Face official source, then falling back to the hf-mirror mirror.

## Supported models and adapters

| Base Model | Task | Adapter Directory | Required VAE |
|---|---|---|---|
| FLUX.2 Klein Base 9B | Text-to-RGBA | `flux2_klein_base_9b_t2rgba` | FLUX.2 VAE (128 channel latent, 2D decoder) |
| FLUX.2 Klein Base 9B | Image-to-RGBA | `flux2_klein_base_9b_i2rgba` | Same as above |
| Qwen-Image-2512 | Text-to-RGBA | `qwen_image_2512_t2rgba` | Qwen-Image VAE (Wan 2.1, 16 channel) |
| Qwen-Image-Edit-2511 | Image-to-RGBA | `qwen_image_edit_2511_i2rgba` | Same as above |

> Adapters are released by [WLuLi/AlphaAnything](https://huggingface.co/WLuLi/AlphaAnything), each about 400–470MB.
>
> The two FLUX.2 adapters were trained on Klein Base and can also be used directly for the 4-step distillation version `FLUX.2-klein-9B` (most cases work as per official instructions).
>
> Only supports the above two types of VAE decoders; other decoders like Qwen-Image 2.1's 64 channel VAE, Wan 2.2, etc., will result in direct errors.

## 📦 Installation

### Manager Installation

Search for **ComfyUI_Alpha_Anything** in the ComfyUI Manager and then Install.

### Manual Installation

```bash
cd ./ComfyUI/custom_nodes
git clone https://github.com/supElement/ComfyUI_Alpha_Anything.git
```

Restart ComfyUI. No additional dependencies: uses Python standard library, LoRA loading via ComfyUI's native LoRA loader.

> Requires a newer ComfyUI (using V3 node API with `io.Custom` ports).

### Model Directory

Adapters are placed uniformly in:

> ComfyUI/models/alphaanything/
>   flux2_klein_base_9b_t2rgba/
>     adapter_config.json
>     pytorch_lora_weights.safetensors
>     alpha_decoder.safetensors
>   qwen_image_2512_t2rgba/
>     ...

- The directory will be created automatically if it doesn't exist.
- Missing any of the three files will trigger automatic download on the first execution of the adapter; download first from `huggingface.co`, then fallback to `hf-mirror.com` if failed.
- You can also manually download the corresponding subdirectory from [Hugging Face](https://huggingface.co/WLuLi/AlphaAnything/tree/main) and place it in the above structure.
- The adapter dropdown defaults to listing the official 4; locally built adapter directories containing `adapter_config.json` will also appear in the list.
## Node Overview

Nodes are located under `alphaanything` category, search `AlphaAnything` to find them.

| Node | Function | Input | Output |
|---|---|---|---|
| **AlphaAnything LoRA Loader** | Loads official LoRA and alpha branch weights, attached to MODEL | `adapter`、`strength`、`model` | `model`、`alpha` |
| **AlphaAnything Element Prompts** | Fits VLM's layer plan (or manual list) into templates, generates prompt list | `vlm`、`use_vlm`、`elements`、`template`、`background` | `prompts`（list）、`with_alpha`（list） |
| **AlphaAnything VAE Decode (RGBA)** | Decodes with native VAE, outputs alpha simultaneously and composites RGBA | `samples`、`vae`、`alpha`、`with_alpha` | `IMAGE`（4 channels） |

- `AlphaAnything LoRA Loader` connects between model loading node and KSampler, text encoding does not need to pass through it.
- `AlphaAnything Element Prompts`'s `prompts` connects to native CLIP encoding node; list is expanded item by item by ComfyUI natively, each element runs a full sampling.
- `vlm` connects to VLM output, `use_vlm` enabled splits automatically by `<ELEMENTS>` / `<BACKGROUND>`; disabled uses `elements` / `background` for manual input, keeping port connections.
- In VLM mode, after each execution, the split results are automatically refilled to `elements` / `background` input boxes for easy viewing and editing (to make edits take effect, close the use_vlm switch); the content used in this queue still uses the refilled content, cache reruns also refill.
- `template` input box has a fixed height of 5 lines; elements are fitted into templates (replaces if `{element}` is present, otherwise appends at the end), background layer commands are used as-is, not fitted into templates.
- `AlphaAnything VAE Decode (RGBA)` replaces normal VAE Decode; `alpha` port connects to LoRA Loader's `alpha` output.
- `with_alpha` is per-layer tagging: Element Prompts' `with_alpha` output matches `prompts` in length (background layer off), connected to decoding node, background layer automatically skips alpha branch, outputs opaque full image; both ports must go through the same chain to ensure per-layer alignment.
- When this port is not connected, the decoding node calculates alpha for all layers.

## Usage

### Text-to-RGBA

1. Load components according to the model's native workflow:
   - FLUX.2: `UNETLoader`（Load Diffusion Model）select FLUX.2 Klein base, `CLIPLoader`（Load CLIP）type select `flux2`, `VAELoader`（Load VAE）select FLUX.2 VAE.
   - Qwen-Image: `UNETLoader`（Load Diffusion Model）select Qwen-Image-2512, `CLIPLoader`（Load CLIP）type select `qwen_image`, `VAELoader`（Load VAE）select Qwen-Image（Wan 2.1）VAE.
2. Empty latent: FLUX.2 use `Empty Flux 2 Latent`（1024×1024）；Qwen use 16-channel `EmptySD3LatentImage`.
3. Text encoding uses native CLIP node; negative prompts can be left empty or a single space.
4. Connect to `AlphaAnything LoRA Loader`, `adapter` select **t2rgba**, `strength` keep 1.0.
5. Sampling parameters set according to official reference: Klein base 50 steps / CFG 4.0; 4-step distillation version 4 steps / CFG 1.0; Qwen-Image 50 steps / CFG 4.0.
6. After sampling, connect to `AlphaAnything VAE Decode (RGBA)`, then save（`SaveImage` can directly save RGBA PNG）.

### Image-to-RGBA

Integrate this extension into the corresponding model's native editing workflow:

- **FLUX.2**: `LoadImage` → `VAEEncode`（FLUX.2 VAE）→ `Set Reference Latent` attached to conditioning; sampling empty latent's width and height match the source image.
- **Qwen-Image-Edit**: `Text Encode Qwen Image Edit`（`image` connects to source image, `vae` connects to Qwen VAE, `prompt` writes extraction command or detailed description, see 「Prompts」）→ directly outputs conditioning; sampling empty latent width and height match the source image.
- `AlphaAnything LoRA Loader` replaced with **i2rgba** adapter, intensity still kept at 1.0.
- Sampling parameters same as above; output still goes through `AlphaAnything VAE Decode (RGBA)`.

> Official scripts will proportionally resize the source image to near 1024² before sending it to the model. In ComfyUI, manually resize the source image to about 1MP and ensure the sampling latent width and height match the reference image.

## Prompts

Official does not enforce a mandatory template, the web demo simultaneously exists with three writing styles, choose one based on the target.

### Text-to-RGBA

Official web's generation examples primarily use **detailed description**: main structure, material, transparency representation (glass, fabric, feathers, paper art), light and shadows, no fixed introductory phrases. For example (Qwen-Image) :

> A glasswing butterfly opens its nearly transparent wings, edged in chestnut and narrow cream bands. Fine dark veins cross the clear membranes, while a slim opaque body, curled legs, and delicate antennae remain sharply defined. Natural-history macro photography with faint blue reflections on the wings.

README / CLI examples often use shorter "description + `isolated on a transparent background.`":

> A delicate glass butterfly with translucent wings, isolated on a transparent background.


- Describe one subject at a time (output only one layer of alpha, multiple targets will merge into the same layer).
- Translucent materials are more effective when described directly in the prompt (`translucent`、`clear glass`、`fine mesh`) than abstractly emphasizing "transparent".
- Unwanted background, clutter put in negative prompts.

### Image-to-RGBA

Web i2rgba examples use "fixed introduction + target description":

> Extract the object described by the text, preserving fine details and transparency: A clear long-stemmed glass holds a coral-red cocktail with large ice cubes and an orange slice. Bright reflections run down its rounded bowl and slender stem to the oval glass foot.

Layered extraction examples use free commands, clearly specifying what to take, preserve original position and transparency, make the rest transparent:

> Extract only the tall clear stemmed cocktail glass on the right, including its complete rounded bowl, thin rim, coral-red drink, ice, orange garnish inside the bowl, slender stem and oval glass foot. Preserve true natural partial transparency through the empty upper glass, glass walls, clear stem and base, with the original reflections and refraction. Everything outside the requested element must be transparent. Do not recenter, resize, crop, restyle or add objects.

Directly providing detailed generative descriptions also works (layer writing style in official combined examples, for image extraction testing matches official results):

> A broad luxurious champagne silk fabric drape lying almost horizontally on an unseen tabletop, with one softly raised folded crest at the right and several smooth gently curved folds trailing toward the left. Heavy fluid satin with muted honey-gold highlights, deep subtle champagne shadows, exceptionally fine woven texture and realistic weighted cloth. A single complete restrained connected fabric shape, low and wide. The entire complete subject is inside generous empty margins, isolated on a genuinely transparent background. Authentic fine material detail, restrained natural colors, soft directional illumination from upper left.

When layering, do not omit the background layer: the background layer is not "rest of transparent", but retains the entire image, removing foreground elements one by one, outputting opaque layers:

> Extract the complete photographic BACKGROUND, keeping the original dark studio wall, the gray stone countertop and the plants behind the glass. Remove only the cocktail glass and drink, both mint leaves, chrome shaker, all words and icons. Reconstruct the wall, foliage and counter only where those foreground elements were removed. Return the entire original rectangular background fully opaque, preserving the original lighting, blur and framing.


- Background layer commands filled into `AlphaAnything Element Prompts`'s `background`（used as-is, placed first), `elements` only put foreground elements.
- The background layer's `with_alpha` is automatically set to off by Element Prompts, connect this output to the decoding node, no need to split branch; the background layer still runs independently sampled, will not appear occasional hollowing.
- Position terms describe based on the **source image** (on the left / the smaller line, etc.).
- Extract one target at a time; if layering, run multiple times.
- Not limited to translucent elements, opaque objects, text, and decorative graphics in posters can also be extracted.
- This extension will not add prefixes for you, text enters the encoder as-is; to replicate official CLI's `--description` effect, include that `Extract the object described by the text, ...` yourself.
## Parameter Description

| Parameter | Description |
|---|---|
| `adapter` | Official 4 adapters + local custom directory (must contain `adapter_config.json`). For text-to-image, choose t2rgba; for image-to-image, choose i2rgba. |
| `strength` | Default 1.0 = official strength. Internally loads LoRA according to `strength × alpha / rank`. |
| `samples` | Sample latent, only take `samples["samples"]` during decoding. |
| `vae` | Must match the adapter family (FLUX.2 with FLUX.2 VAE, Qwen with Qwen Wan 2.1 VAE). |

> `strength` only scales LoRA, does not scale the alpha branch. They are trained together, arbitrarily lowering them will cause RGB to deviate from the training distribution of the alpha branch, it is recommended to keep it at 1.0.

## Known Limitations

1. **Only supports two types of VAE decoders**: FLUX.2's 2D Decoder and Qwen-Image (Wan 2.1) Decoder3d. Other structures (including Qwen-Image 2.1's 64-channel VAE) will error, will not silently degrade.
2. **Only decodes single-frame images**: latent time dimension greater than 1 will error.
3. **Does not support tiled decode**: hitting the tiled path will error clearly. Insufficient GPU memory, please lower the resolution, do not enable tiled.
4. **Adapters must match the base model**: FLUX.2 adapters can only use FLUX.2 VAE, Qwen adapters can only use Qwen VAE; mismatched decoding will error "does not match this VAE".
